# Выключить подпись ИИ

## Что происходит

Хук и проверка (30-04) ловят подпись ИИ уже в сообщении коммита. Источников
подписи два, и оба выключаются настройкой, а не правилом в тексте:

* Claude Code по своей инструкции дописывает в коммит строку соавтора, а в
  PR — строку о том, кем создан текст;
* кнопки «Squash and merge» и «Rebase and merge» на GitHub пересобирают
  коммиты PR и дописывают соавторов (30-03).

## Как правильно

**Claude Code** — один раз на машину, в настройках пользователя (не
проекта: действует во всех репозиториях). Файл — `settings.json` в папке
настроек Claude Code в домашней папке; нет файла — создать. Добавить, не
затирая остальное:

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

Только объектом: `"attribution": false` старые версии не принимают и
пропускают весь файл.

**GitHub** — у каждого репозитория `*-Skill`, сразу после создания:

```bash
gh repo edit <владелец>/<Имя>-Skill --enable-squash-merge=false \
    --enable-rebase-merge=false --enable-merge-commit=true
```

Без gh — `PATCH /repos/{owner}/{repo}` с `allow_squash_merge: false`,
`allow_rebase_merge: false`, `allow_merge_commit: true` (40-03). Проверка:
`gh api repos/<владелец>/<Имя>-Skill --jq
'[.allow_squash_merge,.allow_rebase_merge,.allow_merge_commit]'` →
`[false,false,true]`.

**Другие агенты** — у каждого своя настройка подписи; найти и выключить
так же, в настройках пользователя. Kimi Code, opencode — не проверено.

## Как неправильно

* Полагаться только на хук: клон без `core.hooksPath` или
  `--no-verify` пропустят подпись, проверка истории найдёт её уже после.
* Выключать подпись в настройках проекта: в другом репозитории она
  вернётся.
* Оставлять squash и rebase включёнными в надежде, что владелец не нажмёт
  не ту кнопку.

## Чем подтверждено

2026-10-29: файл настроек создан с блоком выше — в той же сессии Claude
Code перестал требовать подпись. Восемь `*-Skill`: `gh repo edit`, затем
`gh api` по каждому — `false,false,true`.
