# Правила базы знаний (для всех наборов)

Эти правила общие: набор хранит у себя только особенности и строку «общие
правила — соседний скилл skill-skill». Меняется общее правило — здесь, а
наборы получают его через `git pull` в skill-skill (проверки и хук тоже
общие).

**Ценность базы — достоверность.** Запись, которой нельзя доверять, хуже
отсутствия записи.

## Что хранить

Поведение программ и среды, расходящееся с документацией или интуицией;
команды и вызовы, подобранные опытом; приёмы, доказавшие работоспособность;
решения, давшиеся через провалы.

Не хранить: то, что легко найти в документации; устройство кода (оно в
docstring); историю конкретного проекта; пути, имена машин, серверов и
учётных записей; сведения об изделиях и проектах, на которых набор
применялся (40-02).

Проверка на нужность: «если не записать, сколько времени потеряет
следующая сессия?» Меньше десяти минут — не писать.

## Структура

```
knowledge/
├── 00_ПРАВИЛА.md   особенности набора + ссылка сюда
├── INDEX.md        таблица id | утверждение | status | файл + поиск по симптому
├── 10_…/           как вызывать (API, команды; имя раздела — по набору)
├── 20_ПРИЁМЫ/      как работать
├── 30_ГРАБЛИ/      что ломается; каждая запись — потерянный час
└── 40_СРЕДА/       40-01 установка и зависимости; 40-02 особенности репозитория
```

Один файл — одна тема, не больше 200 строк. Имя файла — `<id>_<тема>.md`.
Номер не переиспользуется: устаревшая запись получает `status: устарело`, а
не удаляется. Разделы сверх 10–40 (например, 50_) — по нужде набора.

## Шапка записи и статусы

```yaml
---
id: 30-04
title: Утверждение, а не тема
tags: [...]
applies_to: версии ПО, ОС, агента
status: проверено | не проверено | устарело | действует
verified: дата — КАК проверено
source: эксперимент | практика | документация | перенесено из <набор>
---
```

`проверено` — без `verified` и `applies_to` силы не имеет; всё
непроверенное внутри такой записи помечается «не проверено» прямо в тексте.
`действует` — для правил (00, порядок работы), а не наблюдений. Запись из
соседнего набора, не воспроизведённая здесь, — `не проверено` со ссылкой
на источник.

Тело записи-грабель: «Что происходит / Почему / Как правильно / Как
неправильно / Чем подтверждено».

## Добавление, обновление, удаление

1. Убедиться, что записи нет (INDEX, поиск).
2. Взять следующий номер раздела.
3. Написать по шаблону; строка в `INDEX.md` и в `CHANGELOG.md`.
4. `python tools/check_docs.py --project "<папка проекта>"`, `git diff`,
   коммит, push (40-02).

Правка записи — обновить `verified`; не подтвердилась — понизить до `не
проверено`. Удаление файла и перепись истории — только по команде человека.
Общее для нескольких наборов — сюда, в наборе — ссылка.

## SKILL.md и установка

* **Репозиторий = папка скилла.** Клон лежит в `<папка скиллов агента>/<name>`,
  имя папки = `name` в шапке `SKILL.md`, `SKILL.md` в корне. Нет
  установщиков, переменных `*_HOME`, junction, папки `skill/` (30-01).
* **Никаких путей конкретного агента** в `SKILL.md` и коде: набор копируют к
  разным ИИ. Корень — папка, из которой прочитан `SKILL.md` (в коде — от
  `__file__`); соседний скилл — `<родитель корня>/<name>`. Переменные
  окружения для поиска наборов не читать: устаревшая побеждает. Примеры
  папок агентов — только в 40-01.
* **SKILL.md ≤ 4096 байт** UTF-8 (≈ 1024 токена: он грузится при каждом
  срабатывании), `description` ≤ 1024 знаков и в кавычках (30-06). В нём
  только то, что нужно всегда: что это, корень, первый шаг, быстрый старт,
  железные правила, id записей базы и строка про skill-skill. Таблицы,
  объяснения, ограничения — в базу; ушедшее из `SKILL.md` должно найтись в
  базе.
* Имя репозитория — `RungeKut/<Имя>-Skill`, ветка `main`; имена
  Python-пакетов наборов не меняются.

## Проверка целостности

Перед каждым коммитом и после слияния чужих правок —
`python tools/check_docs.py --project "<папка проекта>"` (в наборе это
обёртка, одинаковая во всех; код — `skill-skill/tools/check_docs.py`).
Все наборы сразу — `python tools/check_all.py` из skill-skill.

* **SKILL.md:** в корне; `name` = имя папки; ≤ 4096 байт; `description`
  есть, в кавычках, ≤ 1024; нет `skill/`, `setup.ps1`, `Install-skill.bat`;
  в наборе есть строка про skill-skill.
* **База:** шапка и поля; `status` из списка; `проверено` с `verified` и
  `applies_to`; id = имя файла и уникален; файл ↔ строка `INDEX.md`, число
  ячеек в строках таблиц; ссылки не битые; ≤ 200 строк.
* **Тексты** (всё, что видит коммит, и `Makefile`): стоп-слова общего и
  своего стоп-листа, слова имени папки проекта (`--project` и
  `git config <name>.project`); старые имена репозиториев с окончанием
  «Kit» (кроме `CHANGELOG.md`).
* **Код и SKILL.md:** нет путей агентов, переменных `*_HOME`, `mklink`,
  `skill/SKILL.md`.
* **Локальное:** общий стоп-лист есть; стоп-лист и `local/` не под git;
  изображения под git — только в `examples/`; `tools/check_docs.py` —
  та же обёртка, своих `check_msg.py` и `tools/hooks/` нет.
* **Git:** `core.hooksPath` = `../skill-skill/hooks` (в самом skill-skill —
  `hooks`); автор задан для клона, адрес публичный; ветка `main`; origin
  `…/<Имя>-Skill.git`.
* **История** (`git log --all`): нет трейлеров соавторов, «Generated with»,
  🤖, noreply-адресов ИИ; автор и коммитер — не `*.local` и без стоп-слов;
  стоп-слов нет в сообщениях. Старые коммиты исправляет только перепись
  истории по команде владельца — до неё отчёт помечает их отдельно.
* Особое набора — `tools/kit_local.py` (описание интерфейса — в шаблоне).

После `git pull --rebase` проверку прогнать заново и перечитать слитое: git
сливает текст, а не смысл.

## Язык

Русский; имена функций и API — как есть; без «обычно», «как правило» в
записях `проверено`. В коде комментарий запрещён по умолчанию — он должен
доказать право на существование (объясняет «почему», а не «что»);
пояснения — в docstring.
