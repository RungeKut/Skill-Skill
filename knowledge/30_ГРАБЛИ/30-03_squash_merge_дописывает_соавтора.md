# Squash-слияние дописывает соавторов

## Что происходит

Кнопка «Squash and merge» на GitHub собирает коммиты PR в один, автором
делает того, кто нажал, а авторов исходных коммитов дописывает трейлерами
строками соавторства. Rebase-слияние на GitHub пересоздаёт коммиты с другим
коммитером. В истории появляются трейлеры соавторов, которые
`check_docs.py` считает нарушением, и теряется прозрачное авторство.

## Почему

Так GitHub сохраняет авторство при squash. Правило наборов: автор коммита —
тот, кто его сделал; соавторов в сообщениях нет (40-02).

## Как правильно

Владелец сливает PR сам, локально (40-02):

```bash
git fetch origin pull/<N>/head:pr-<N>
git diff main...pr-<N>                  # глазами; check_docs; сообщения коммитов PR
git merge --no-ff pr-<N>
git push
```

Коммиты автора PR остаются с его авторством; слияние — коммит владельца.

## Как неправильно

Squash или rebase кнопкой на GitHub; `cherry-pick` чужих коммитов.
